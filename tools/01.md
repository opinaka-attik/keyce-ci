## 🤔 Deux cas possibles

### Cas 1 — Le repo GitHub **n'existe pas encore**
```bash
# 1. Initialiser git dans ton projet
git init

# 2. Créer les 3 branches directement
git add .
git commit -m "etape-1 : API + Docker"
git branch -M etape-1-api

# Créer l'étape 2
git checkout -b etape-2-tests
git commit --allow-empty -m "etape-2 : ajout pytest"

# Créer l'étape 3
git checkout -b etape-3-ci
git commit --allow-empty -m "etape-3 : ajout GitHub Actions CI"

# 3. Lier au repo GitHub et pousser
git remote add origin https://github.com/TON_USER/calculator-api.git
git push -u origin --all   # pousse TOUTES les branches d'un coup
```

---

### Cas 2 — Le repo GitHub **existe déjà**
Oui, dans ce cas **passe par une branche + Pull Request**. C'est la bonne pratique professionnelle :

```bash
# 1. Se mettre à jour depuis GitHub
git checkout main
git pull origin main

# 2. Créer une branche pour ton travail
git checkout -b etape-3-ci

# 3. Ajouter et commiter les fichiers
git add .
git commit -m "feat: ajout GitHub Actions CI"

# 4. Pousser la branche sur GitHub
git push origin etape-3-ci
```

Ensuite sur GitHub :
```
Repo → onglet "Pull Requests" → "New Pull Request"
base: main ← compare: etape-3-ci
→ "Create Pull Request" → "Merge"
```

---

## 🎯 Recommandation pour ton cas pédagogique

Puisque c'est un **projet d'apprentissage**, la stratégie la plus claire est :

```
main (vide ou README)
├── etape-1-api    ← push direct ✅
├── etape-2-tests  ← push direct ✅
└── etape-3-ci     ← push direct ✅ (la CI se déclenche ici !)
```

```bash
# Pousser les 3 branches d'un coup
git push -u origin --all
```

Pas besoin de Pull Request pour un projet solo pédagogique — les PR sont utiles quand **plusieurs développeurs** collaborent et doivent relire le code avant de merger. 😊
